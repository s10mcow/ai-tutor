# Domain documentation

This project has one domain context. Read the root glossary before exploring or implementing domain behavior. Read the relevant decisions in the ADR directory, and surface conflicts instead of silently overriding them.

Use the glossary's vocabulary when naming domain concepts in code, tests, issues, and review findings. Update it when a term is actually settled. Keep implementation details out of glossary definitions.

The glossary and ADRs already exist. Create additional decisions only when an actual, consequential trade-off needs its rationale preserved.
