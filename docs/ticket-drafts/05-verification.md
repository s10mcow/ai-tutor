# Ticket 05 verification and coaching contract

## Delivered behavior

The typed activity has explicit choices to compare another way, check supplied evidence, question a Tutor claim, explain differently, start easier and request a fresh challenge. Own explanations and revisions still use **Share attempt**, preserving the Portfolio distinction between Learner-authored attempts and app-suggested requests. The prompt beside the composer invites reasons and a change of mind without grading. Secondary coaching choices open above the composer and support keyboard Escape and return focus.

The live Sol teaching policy is in `lib/coaching-policy.ts`, separate from the provider transport. It asks for reasons after a bare answer; separates a correct result from incorrect reasoning; treats simple or repeated confusion as enough to change approach; invites alternatives, supplied-evidence checks and warranted revisions; welcomes valid challenges while avoiding automatic agreement; and withholds solutions on a fresh challenge until help is requested. It forbids grades, unsupported mastery, invented verification, unprovided emotion inference and pressure to try risky biking activities. Activity purposes and the bounded Learner-stated notes retain their existing meanings.

A completed `fresh` action pins its Tutor reply beside the original question. The following attempts are visibly labelled **Fresh challenge attempt**. The ordered exchange, including previous coaching and the fresh prompt, reaches the same Tutor adapter so the new attempt is not assessed against the old question. A later correction resets the fresh focus. No automated correctness, quality or mastery judgment is added to text coaching.

**Take a break** saves the scratchpad, unsent message and its selected purpose on the owned temporary session. The paused view leaves the question and conversation readable and offers **Resume activity**. A reload, process restart or profile switch restores the paused work; no provider call, Portfolio save or lasting note is made. The fixed expiry is unchanged and is stated in the UI. Ending still deletes the activity immediately. Outside an explicit break, unsent composer/scratchpad edits remain temporary.

## Application and extension contract

- `CoachingIntent` adds `alternative`, `evidence`, `challenge`, `different`, `easier`, `fresh`. All use the existing bounded, authorized and replay-safe action submission and metered direct Sol dispatch. The scripted preview supports each intent and remains clearly labelled as a fixed fictional demonstration.
- `LearningSession.breakState` is null or `{ paused, scratchpad, message, intent }`. Migration `05-coaching-break.sql` stores it on the expiring session; it is never sent as Tutor context. `breakRevision` is an integer that increments for each new pause checkpoint and persists after resume and subsequent actions. Async speech/media work can compare that revision before delivering a result to reject an intervening break.
- `POST /api/learners/:learnerId/session/:sessionId` accepts `{ intent: "pause", scratchpad, message, messageIntent }` or `{ intent: "resume" }`. Draft limits are 4,000 scratchpad and 2,000 message characters; whitespace is preserved. Family, intended Learner, same origin and live session checks remain required. The session lock serializes a break with sends; pending replies prevent pausing and paused sessions reject model submissions. Game controls remain owned by the game module.
- An unchanged pause replay preserves the existing checkpoint and revision; changed drafts while already paused return 409. Resume is repeatable and retains the checkpoint so an unconfirmed response/reload can recover it. The next new coaching action consumes the saved draft checkpoint without resetting `breakRevision`; normal later unsaved edits are not an automatic archive.
- `currentFreshChallenge` derives the current fresh reply from completed actions after the most recent correction. The reply remains Tutor-authored. Portfolio saving still selects explicit attempt text only, never this prompt, control text, supplied evidence automatically, or Tutor prose.

## Verification and limits

The adopted Playwright boundary uses the real browser, Better Auth, application HTTP routes and isolated PostgreSQL. Only the external Tutor/Responses services are controlled. The reasoning scenario failed at the absent comparison control, adaptive scenario at the absent different-explanation control, and persisted-break scenario at the absent break control before each implementation.

The scenarios cover correct answer/wrong reason, alternatives, supplied evidence, revision, a challenge to the Tutor, repeated simple confusion, a changed example, easier start, fresh problem with less help, reload, pause/resume across web restart and profile switching, unauthorized/mismatched-Learner resume, unchanged expiry, no dispatch while paused, checkpoint replay and retained break revision. The direct Sol fixture asserts original/fresh context and shared measured usage; these assertions check application routing and billing contracts, not actual pedagogy.

[The synthetic real-model evaluation](../evaluations/05-reasoning-coaching.md) defines six scenarios, two age profiles, repeated runs, explicit behavior scores and blocking safety/unsupported-confidence flags. It has **not run**. Real teaching quality, suitability for the Learners, provider eligibility/credits/under-13 retention, hosted access, scheduled purge and backup retention remain pilot gates. No real child data, paid provider request, cloud resource or external account change was used.

The React guidance was applied to component boundaries, browser-safe imports, controlled fields, labelled controls, keyboard focus, bounded history and existing abort/unmount protection. A 1366×768 screenshot exposed the tall composer; secondary controls were compacted, chat scrolling bounded and the current work kept visible while the page scrolls.
