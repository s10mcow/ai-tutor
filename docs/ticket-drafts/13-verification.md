# Ticket 13 verification: public sources and claim checking

## Application contract

`Check public sources` submits an explicit `research` action through the existing authenticated, same-origin session route. Only `id`, `intent`, and the claim text are accepted. Family and Learner authorization, activity expiry, break state, picture confirmation, action ordering, idempotency, and deliberate retry remain shared with coaching. Research sends only the explicit claim and the tutoring/search policy to the provider, never the family identity, learning notes, other Learner data, or the entire private conversation.

One direct GPT-6.1 Sol Responses request uses only hosted `web_search`, `max_tool_calls: 1`, `parallel_tool_calls: false`, `tool_choice: required`, default returned-token budget, low search context, 2,000 output tokens, Standard processing, disabled implicit caching, `store:false`, foreground operation, and no automatic application retries. The application has no raw URL fetch endpoint, function dispatcher, computer control, MCP connector, purchase, messaging, or account-creation tool. Unsupported capability settings are rejected before dispatch. A provider response that contains an unexpected tool is not usable evidence.

Source evidence is accepted only from a completed search action's structured `action.sources`; plain citation-shaped text and URL annotations alone cannot establish retrieval. Inline citations must match a retrieved source and valid text offsets. Links permit public-looking HTTP(S) hostnames only: no credentials, non-default ports, IP literals, local/internal/test domains, or executable schemes. React renders all titles and content as text; links open with no referrer and `noopener noreferrer`. The application never fetches a returned URL. Source quality and claim truth still require human/model evaluation; a prominent note says finding a source does not prove a claim. An expanded, keyboard-accessible source dialog makes the cited explanation readable on a 1366×768 laptop. Missing retrieval or missing supported citations yields an explicit uncertainty message rather than the provider's unsupported assertion.

Learners can use `Revise my conclusion`; follow-up text coaching receives the earlier source evidence as untrusted context, with no tools. Only the Learner's own revision text is eligible for an explicit Portfolio save, alongside ordinary attempts. Search output and source metadata are not saved as Learner-authored evidence. Research metadata is on `learning_action`, sharing session ownership and deletion/expiry. Billing records contain usage/identifiers, not claims, URLs, titles, or replies.

## Provider controls and cost policy

Official OpenAI documentation checked on 2026-11-16, without credentials, model calls, provisioning, or account changes:

- [Sol model](https://developers.openai.com/api/docs/models/gpt-6.1-sol): web-search support and 922,000 maximum input tokens.
- [Responses creation reference](https://developers.openai.com/api/reference/resources/responses/methods/create): `max_tool_calls` caps all built-in calls in one response; further attempts are ignored. `max_output_tokens` includes reasoning output.
- [Web search](https://developers.openai.com/api/docs/guides/tools-web-search): completed search metadata, `include: ["web_search_call.action.sources"]`, URL citation offsets, required clickable inline citations, and search/open/find actions. Low search context is not an exact token limit. Returned-token budget supports default/unlimited, not a numeric ceiling. The web-search context has a 128k limit; this app deliberately reserves the larger Sol ceiling instead of interpreting that as the whole request's cost.
- [Pricing](https://developers.openai.com/api/docs/pricing): Sol Standard long-context input $4/M and output $15/M; search $0.01/call plus search-content model tokens. Search content is fed to the model as input. Open/find events are not automatically charged as searches.
- [Managing tokens](https://developers.openai.com/api/docs/guides/advanced-usage#managing-tokens): response usage reports the API call's tokens. [Tool flow](https://developers.openai.com/api/docs/guides/function-calling#the-tool-calling-flow) describes the model/tool/model cycle.
- [Data controls](https://developers.openai.com/api/docs/guides/your-data): feature/account eligibility and approval are distinct from `store:false`; web search has separate live/cache-only HIPAA/BAA caveats, which do not themselves establish child-data eligibility.

Policy `sol-research-standard-conservative-2026-11-16` reserves **$7.446** before dispatch in the same transactional ledger as text, image, and speech. This is a deliberately conservative derivation: with one built-in call, budget both pre-tool and post-tool inference at the entire 922,000-input/2,000-output ceiling, plus one search fee: `2 × (922000 × 4 + 2000 × 15) / 1e6 + 0.01`. Output is actually capped at 2,000 across the response; reserving it twice gives extra headroom. This is an inference from the documented bounded tool cycle and model limits, not an assertion that low search context provides an exact total-token ceiling. No background agent, continuation, secondary model, or hidden application retry is enabled.

After a completed response with valid authoritative no-cache usage and a valid bounded tool-event list, account all aggregate input/output tokens at long-context rates plus the observed search fees. This safely avoids guessing which inference pass crossed the pricing threshold. It is labelled conservative accounted usage, not exact provider billing. A fixture with 10,000 input and 300 output tokens plus one search accounts $0.0545 and releases the proven unused part of the reservation. Missing, contradictory, out-of-bounds, failed, or unexpected-tool usage keeps the full reservation unresolved. Failed lookup never implies zero spend. An explicit retry is a separately reserved attempt; duplicate completed/pending action IDs do not redispatch.

Live research requires the existing exclusive-ledger subscription funding evidence plus `responsesSearchApproved: true` on matching, unexpired retention evidence. Text-only approval is insufficient. No extra generic operator attestation is introduced. Fixtures are visibly fictional and bypass live account evidence only outside production.
